# V1.09 研究导入回执

`research.importDocuments` 的请求仍采用 GaoAction V1，将当前文档的独立副本交给搞研究审核。未保存纯文本标题没有扩展名时，按编辑器的实际格式补齐后缀；不再误问源码转 TXT。LaTeX 等研究端不接收的源码仍需明确确认转成 UTF-8 TXT，原件及未保存状态保留。

研究导入结果只报告处理状态，不携带编辑附件或原件引用，也不会保存当前编辑器。结果使用新的 UUID、nonce 和有效期，保持原动作和 `inReplyTo`，来源为研究应用、目标为文件应用，`parameters` 必须为空。接收方核对原请求后才接受状态。

回执 `provenance` 的必需字段：

- `requestManifestSHA256`：原请求 manifest 原始字节的 SHA-256。
- `workflowState`：完成时为 `imported`，其他状态与顶层 `status` 一致。
- `sources`：完整且无重复地覆盖请求的每个输入，包含精确的 `sourceItemID`、`sourceSHA256` 和 `status`。单项状态为 `imported`、`failed`、`cancelled`、`pending` 或 `unsupported`。

完成必须报告全部来源已导入；部分完成必须有成功和未成功的来源；等待、失败、取消和不支持不能报告已导入。缺项、来源或请求摘要不符、伪完成、带附件或请求参数的结果会被拒绝，原有文档和处理记录保留。提供方可附带导入计数和业务回执编号，但这些字段不改变来源校验和结果语义。

已接受部分完成后，只能保持部分完成或推进为全部完成；每个已导入来源也必须在后续回执中继续保留。新记录以可选字段保存已导入来源，旧记录不补写。旧版部分完成记录若缺少逐来源进度，仍可读取并识别原回执重复，但只有全部完成的新回执能安全消解未知进度。

研究端必须在真实导入、索引及业务记录持久化完成后报告完成。已经提交资料但尚待恢复的中断应保持等待，不能先报告终态失败再恢复成完成。重复信封不重复执行；提供方重发结果也不能重新导入资料。来源声明与摘要用于本机交接关联，不等同于应用身份认证。

编辑返回继续由用户控制：研究原条目“在搞文件中编辑…” → 文件“导出编辑副本…” → 研究原条目“导入编辑新版本…”。研究端检查原版本并由用户选择新版本或新附件。`documents.open` 的打开回执、导出成功和实际导入完成分别记录；不提供自动替换，也不声称人工选择的文件具有可机器证明的导出谱系。

真实安装版本、正常界面往返和未具备条件的验收另行记录；无窗口协议检查不替代这些实际流程。
