# 搞文件 V1.06

V1.06 / build 7 补全文档与 OCR 交接处理链，保留 LaTeX、Markdown 为核心、PDF 叠加编辑、Office 只读和便笺附属的定位。

- OCR 返回保持 `ocr.files` 原动作，按持久化请求、`inReplyTo`、输入摘要和结果附件关联核对；文字进入新未保存标签，PDF 打开新副本。来源信息区分识别引擎、版本和逐页状态。
- 未保存 PDF 可明确发送当前编辑副本或磁盘版本。当前副本使用实际编辑器模型并提交表单输入，不依赖延迟恢复稿。PDF 来源可靠时核对页面几何和文字层，来源不足时明确限制。
- 修复导出副本时误删目标的风险：拒绝源/原件及同一文件身份，先复制并核验，覆盖其他目标前保留快照，冲突和失败保留现有文件。提供方不可用时支持多文件本地导出。
- 当前文档可作为副本交给搞研究，经对方复核导入；LaTeX 经用户确认发送 UTF-8 `.tex.txt` 源文本副本，排版 PDF 需先编译并打开再发送，不支持的非文本格式明确拒绝。当前文档不会被自动保存。能力发现兼容 V1 动作数组与动作字典，发送时仍核对实际安装版本和参数。
- 搞整理所选文档由本端独立核对权限；待处理、部分完成、失败、取消和完成分别记录，重复不再打开，中断不自动重放。坏、缺失、过新或冲突的交接历史及来源副本会停止处理。

OCR 由本机搞截图提供，搞文件没有新增独立 OCR 引擎。LaTeX / Markdown 内核、Office 只读保护及原资料路径保持；私有文档、便笺附件、恢复稿和长期备份不进入发行包。

本版使用本地签名，未公证。未运行冒烟测试，未启动 App 窗口，NSWorkspace 实际应用 GUI 往返未验收。单元、非 GUI 生产链、安装和资料核验的实际结果见 [验证记录](Verification-V1.06.md)。
