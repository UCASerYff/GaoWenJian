# V1.08 状态回执与研究端待配合项

搞文件结果 writer 已修正为 `parameters: {}`，无错误时不写 `errorCode`。仍保留原请求的 `action`、`inReplyTo`、来源/目标声明及实际业务状态。`documents.open` / `documents.newText` 的回执只报告打开或取消，零附件、`saved: false`；不会自动返回编辑附件。原请求的标题仍用于创建文档，不放进结果参数。

本轮对研究 V4.05 的只读核对发现：`research.importDocuments` 审核成功只执行本地导入并显示反馈；拒绝只关闭审核。两条路径均没有生成并发送机器结果，因此搞文件仍等待回执，不能把本地成功提示等同于调用方收到完成状态。

研究端后续需要在用户复核后生成真实结果，并提供明确的发送动作：新结果 UUID、原请求 ID 作为 `inReplyTo`、相同原动作、正确来源/目标、空结果参数、当前有效期；无错误码时省略该字段。实际完成、部分完成、失败、取消应分别反映真实结果，禁止重复执行导入以补回执。附件和 provenance 需符合双方约定及严格校验，不得把私有原路径或整库资料放入结果。

研究编辑返回仍使用人工流程：研究原条目“在搞文件中编辑…”→搞文件“导出编辑副本…”→研究原条目“导入编辑新版本…”，由用户选择替换或关联新附件。若后续提供自动附件返回，应另立明确接口，保留原件摘要与冲突检查，不把打开状态伪装成编辑完成。

本轮未修改研究或其他兄弟项目。搞整理未安装，其 `files.choose` 真正往返按用户要求暂不验收。
